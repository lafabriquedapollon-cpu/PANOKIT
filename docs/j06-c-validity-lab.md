# J06-C1 — validité et revalidation des devis LAB
No public route, production migration, payment, or checkout. Existing B route unchanged; new authenticated loopback endpoints POST /lab/j06/lease and /lab/j06/revalidate. The former calculates and persists the quote and issues a fresh 256-bit random token in one SERIALIZABLE transaction. Only SHA256(token) stored. PostgreSQL clock defines 15-minute LAB expiry (design assumption, not commercial policy). Revalidation accepts exactly token, reads immutable historical quote, recomputes using current approved industrial/tariff snapshots and original selection, checks fingerprint and expiry again without extending it. Historical quote and lease never orderable. No promise of validity after transaction commit: future checkout must revalidate atomically at its own acceptance boundary. Runtime DB role and HTTP laboratory capability remain trusted; no browser/public token transport. Separate lease tokens per explicit issuance; no claim of issuance idempotence. Existing quote fingerprint dedup stays unchanged. Old quotes remain history. Eight C cases added to existing sixteen B cases; CI results not presumed.
