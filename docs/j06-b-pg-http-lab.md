# J06-B — PostgreSQL 17 + HTTP LAB
GOAL: real disposable PG17 persistence and transport, not a production migration.
Same disposable DB as J03 so industrial and tariff approvals read in one MVCC snapshot. J06 owner NOLOGIN reads J03 tables through narrow grants; existing J03 roles and functions unchanged. Separate editor, approver, revoker, trusted runtime; no direct table access for login roles. Tariff and destination mapping immutable per revision, decisions append-only, optimistic revision lock, terminal withdrawal. Mapping is synthetic and tied to immutable tariff revision, not a geocoder or real address. Approval identifies tariff revision/digest; mapping is stored in the same immutable row, not independently cryptographically signed.
Engine J06-A unchanged. Dedicated runtime connection verified by session/current role and DB name; SERIALIZABLE transaction, one snapshot, immutable historical quote keyed by fingerprint, identical replay returns same result, failures rollback; commit ambiguity and serialization conflict fail closed, retry explicitly by caller. No quote expiry or live checkout token. Runtime is trusted to submit calculated document; SQL persistence validates binding and approvals, not an independent recomputation of all money fields. Owner/superuser privileged access outside threat model. No actual tariff approval workflow UI.
HTTP listener exclusively 127.0.0.1 ephemeral port, random capability, rejects Origin, bounded body and JSON content, no CORS. Created only by test harness, no AppModule, route/public frontend/DB credentials or real data. No deploy. Tests 16 planned on pinned real PG17, no results presumed. Remaining: additional adversarial qualification, persisted quote expiry and acceptance checks, real zone resolver/admin UI, HTTP LAB frontend states, checkout and security admission.
